# 共同恢复 SFT 与训练后验收

2026-10-11，SGT（UTC+8）。在共同恢复 SFT 训练前固定本计划。原六个失败窗口、两次观察修复的成功与失败均保留；本批继续完成第一步，不启动 M2-plain 性能对照。

## 训练与共同初始化

使用 `history_features_recovery_v2` 和 `single_tool_portfolio_v1`。新示范仅依据当前实际仓位和最后一次被拒的总目标仓位，选择合法方向并保留目标；容差内使用 hold。示范来自原 R5 八个 Train 窗口的固定合法买入前缀，不用未来收益选择恢复标签，不将六个失败窗口加入训练。

固定 192 条恢复示范，加 192 条按预定配额和哈希顺序选择的原正常策略示范，保留原回放的 prompt/completion 字节。原回放仍包含已有离线财务教师及其先验，不能将这些标签解释为新的纯接口教师。另留 24 个不同日期和目标组合的 Train 状态，不参与本次 SFT；它们与恢复训练、原回放及已知失败窗口的日期隔离依据保存在数据清单。

共同 SFT 从原共同 SFT 初始化，只训练一次：seed42、LoRA rank16/alpha32、3 epochs、micro-batch1、梯度累积16、学习率 `5e-5`、completion-only、8192 token 上限且不截断，共 72 次优化更新。数据、代码、训练及合并回执在实际训练前冻结；所有后续臂从同一新合并权重初始化。

## SFT 门禁与最终复评

SFT 使用两个请求 seed 身份，短测为原8状态加新24状态，每状态 greedy1、sampled4，共320条；原8窗口从现金初始状态完整运行，共80条。全部400条执行完毕且通过行为与独立原始记录审计后，才进入新 RL 检查。

最终统一复评 SFT/M1/M2、seed42/43 六个身份：960条短测、240条完整回合，共1200条。SFT 使用同一份权重，两个身份及重复验收均不算独立训练样本。

- 所有短测最多四次模型请求，已知失败与正常状态均须合法推进；不改写动作，不自动 hold、不自动重试。
- 新24状态另设接口恢复验真：首次合法推进须采用当前接口要求的方向、同一 symbol、保留最后请求的总目标仓位（数值容差 `1e-12`）；目标在接口容差内须由模型选择 hold。该项强于一般合法推进，仅证明接口目标恢复，不证明金融决策最优。教师字段不追加到模型输入。
- 完整回合保持总请求上限256，首次 invalid 后最多四次后续请求到合法推进；信息工具也消耗预算。原8窗口全部到达真实终点；不完整轨迹不填造终局财务指标。
- 提交、原始 token、请求 seed、状态链、恢复事件、成交、费用与终局财务结果必须接受独立审计。相同动作的旧版/v1/v2账务严格比较已通过；后续源码变更若影响环境，重新核验。

## 训练后的最小 RL 检查

新 M1/M2 各使用 seed42/43，从同一新 SFT、相同观察版本和同 seed 的共同 critic 初始化重新训练，actor LR `1e-7`、critic LR `1e-6`、M2 eta `0.25`，其余共同惩罚和训练合同沿用。各臂只跑一个新训练轮次、actor/critic各一次更新；实际各消费原八窗口中的前两个，每窗口4个 rollout，共32条训练轨迹。原生完整评估各40条，另有两个SFT身份各40条，共240条原生评估；保留其失败。

原生 Agent-R1 仍只有256总交互上限，没有逐 session 四步门禁；它的成功不能代替后续严格验收。该一轮检查用于观察共同恢复能力经一次 RL 更新后是否保留，不支持四轮训练稳定性或 M2 方法优势结论。后续正式性能对照须全部重新从同一新 SFT 开始，并在最终四轮 checkpoint 重新执行恢复验收。

串行运行使用既有 GPU holder 租约与独立 service。专用一轮磁盘门槛须以当前 optimizer 交换顺序和真实模型参数/导出清单验证；不得降低通用多轮磁盘门槛。所有失败保留，正式 Valid/Final OOS 不打开。
