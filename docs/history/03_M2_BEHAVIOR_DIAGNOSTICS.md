# 阶段三：从全 hold 到共同初始化方向（9 月 9—12 日）

整理日期：2026-09-14。本文合并工具、观察、任务理解、交易转移和动作覆盖诊断；
完整计划、逐项测试与来源哈希见[原文归档](../archive/README.md)。

本阶段修复了确实存在的接口与信息丢失问题，也发现：**能读懂事实、能生成合法买入，
仍不等于会稳定形成有差异的交易轨迹。** 这些实验都是固定 Train 状态下的诊断，未更新模型，
不是 M1/M2 的训练效果。后续共同冷启动的实际工作见[9 月 13—14 日文档](../README.md#近期文档原样保留)。

## 已确认并修复的问题

| 问题 | 处理 | 不能据此推出的结论 |
|---|---|---|
| 工具 schema 丢失范围、长度、默认值和额外字段限制 | 从真实参数模型导出完整 schema，保留原解析及执行校验 | 修复 schema 后 4B 首步仍全 hold；不能称为行为已修复 |
| 旧日志仅存响应 hash，缺环境错误原文 | 可选记录输入/输出、token IDs、传递的采样参数及真实 env.step/成交 | 新批错误分类不能倒推旧 R5 的 131 次 invalid 原因 |
| 连续调用不同股票时，前一次计算值丢失 | 显式 history_memory_v1：最多 20 条 compute/retrieve 结果、检索最多 2 条、4096 字节；保存 as_of，淘汰可见，跨 sibling/reset 隔离 | 跨股票正确性由 CPU 测试覆盖；当时模型成功 compute 仍几乎只针对 AAPL |
| 不清楚当前可计算历史数量 | 显示与工具实际 PIT 选择一致的 close 数量，首日缺历史不伪造数据 | 添加历史提示反而与 1.7B 工具循环相关，不能直接升级为默认训练观察 |

买卖分支经真实解析、环境和 next-open 成交路径验证可用；未发现输入被写死为 hold、
4B 请求 seed 碰撞或缓存重复回答的证据。训练 temperature=1、评估=0 的配置/传递检查通过，
但旧日志不含全部引擎收据，不能把配置检查当成所有历史请求的现场复核。

## 实验结果与决策

| 批次 | 固定范围与结果 | 保留结论 |
|---|---|---|
| 首步接口诊断 | 48/48 响应完整；4B 的旧 schema、修复 schema、追加中性目标各 8/8 hold | 1.7B 的 8 次 invalid 中 7 次缺真实历史、1 次 lookback 越界；加目标后全 hold，未采用该提示为默认 |
| 完整观察诊断 | 32 条中 25 完整、7 耗尽 256 次请求；4B 两组各 8/8 完整；1.7B legacy 8/8，新观察 1/8 | 2593 次响应全部正常结束，失败是工具循环，不是 4096-token 截断；全部零成交 |
| 观察因素与奖励诊断 | 96 条中 70 到终局、26 耗尽 64 请求；1.7B raw/memory_only 各 16/16，history_only 5/16，both 1/16 | 历史提示表达是排查重点；不能把 HORIZON_REACHED 因枚举不同当作完整。4B features 与 1.7B raw 各一笔买入，仍有 94/96 无持仓 |
| 1.7B 语义说明 | 64 条：memory_only 15/16、availability 5/16、time_semantics 0/16、组合 0/16 | 更明确说明仍未解决循环；987 次合法 compute 重复同日同参数。唯一买入轨迹也未达终局 |
| 4B 事实理解 | 64 次答题全部正确，448/448 个事实正确 | 有明确参考定义；答案只评分、不执行交易，不是 64 条交易轨迹 |
| 4B 定义/目标转移 | 64/64 完整，1029 请求、2 invalid；仅原 features 对照有一笔 AXP 成交 | 新增定义、目标及两者组合的 48 条全部现金；7/8 条件×窗口的 siblings 无财务差异，未采用新提示为默认 |
| 4B 单步动作覆盖 | 1024/1024 完整响应，23 笔 buy 全成交、1 次空仓 sell 被拒 | 成交率 2.25%；20 笔是同一窗口 AMZN 目标 50%，其余 V 两笔、GS 一笔，均为 10%；覆盖少且集中 |

单步动作覆盖的 1024 次是每次重置后各执行一步，不是 1024 条完整轨迹；20 笔相同 AMZN
也不是 20 个独立市场案例。50% 目标可合法成交，因为 30% 集中度参照是评分软惩罚，非硬限。
不能把成交合法等同于风险管理良好。

交易转移批次的唯一 AXP 轨迹净收益为 **0.291835%**，同期 benchmark **3.882613%**，
Y **−4.340712**；它发生在此前同窗、同日、同 sibling 身份，非新的独立市场样本。
hold 与 abstain 都保持仓位并推进日期，二者文本比例改变不能当成持仓策略改善。

## 奖励与信息核验留下的结论

固定六种脚本策略×两个 Train 窗口的 CPU 核验完成 240 次推进、20 笔成交与 180 项终局字段。
非终局 reward 为零，终局 Y 与独立账务重算一致；脚本买入持有在部分情形可高于现金，
集中度软惩罚也生效。**没有发现账务/奖励分支强制让现金占优的错误**；脚本结果不是模型策略，
也不能解释 fresh 模型的内部选择。

PIT 数量、20 股五日指标、记忆来源及真实输入经过核对，没有用未来行情补齐首日缺失。
4B 能正确回答“5 个 close 对应 4 个历史 return”等事实，但这不能证明它会从旧裸表中
自发理解或在投资中使用这些信息。模型给出的“信息不足”理由也不等于已验证的内部解释。

## 阶段收束

仅增加 schema、历史说明、定义或一句收益目标，没有形成稳定改善；1.7B 的多个新增说明
甚至损害完整率。研究重心随后转向 4B 的共同探索/初始化，以实际交易、股票覆盖、仓位、
成本、完整性及 siblings 财务差异作为读数。这里没有把某个提示升级为正式默认或手写交易策略。

动作概率评分另有 **7/8 校准通过、1/8 失败**，不能用未校准的候选文本概率选择提示或动作。
相关排查已单独收束于[阶段四](04_INFERENCE_PROBABILITY.md)。
