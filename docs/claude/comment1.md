## 先说现状

**现在的证据离顶会差得远，而且照目前的节奏，再跑几个月也补不上。**

| 维度 | 现在有什么 | 顶会至少要什么 |
|---|---|---|
| 主结果 | M2−M1 ≈ +0.08–0.09 pp。单 seed，每臂 2 轮更新，4 个 Train 窗口 | 多 seed 且显著，样本外数据，训练到收敛 |
| 训练量 | 每臂 2–8 次 actor 更新，4B 全参数，跑两轮约 35 分钟 | 每臂几十到上百次更新，算力能负担 ≥3 个 seed |
| 新颖性 | 9-04 评审的判断是：以新 estimator 立论，存活率 <15% | 需要一个讲得清楚、能被实验验证的机制 |
| 样本外测试 | Final OOS 只有 1 个 83-session episode | 有足够多的独立窗口，能做配对检验和置信区间 |
| 对照组 | M2-plain 还没跑；A1 和正式 Valid 也都没跑 | 完整的消融阶梯 |

最近一个月的时间主要花在工程上：拒单罚实验因为排不到 GPU 超时（0 条轨迹），低显存 Adam 第一次 OOM，靠显存交接才跑通，另外还有 R1–R5 五轮修订。这些工作本身是扎实的。问题在于，在共享单卡上跑 4B 全参数，物理上就做不出顶会要求的统计量。

## 建议的下一步，按优先级

### 1. 确定论文主张：围绕"共同市场路径"立论
9-04 评审已经指出了全仓库最值得写的一点。四条 sibling 面对的是逐 bar 完全相同的历史行情。组内中心化在构造上就消掉了市场运气这个共同外生冲击，相当于 common random numbers 式的配对识别。WebShop、ALFWorld 这类环境里外生噪声接近零，没有这个结构。

建议主张写成 **"exogenous-noise-paired credit assignment for replay-based agents"**，不要写成"又一种 step credit estimator"。这样研究简报里的第 5 类步骤（因市场噪声偶然盈亏）就成了论文的核心。

### 2. 加一个能直接证明这个机制的消融（成本低，最关键）
- **打乱市场路径**：让四条 sibling 各自面对不同窗口或不同行情路径，其他设置不变。如果 M2 的增益消失，就直接说明增益来自共享外生路径，而不只是方差缩减。
- **M2-plain**：S = Y_i − Ȳ_g，不按动作分组。没有它，就只能说"注入了组相对终局信号"，不能说"按动作条件化"。
- **GiGPO 退化**：实测跨 rollout 的精确状态碰撞率，说明 GiGPO 在这里退化成纯 GRPO。按评审的说法，这几乎没有成本。

### 3. 先做一个合成环境，用很小的算力拿到"机制图"
做一个可控的模拟市场，收益 = 可学的 alpha + 可调强度的外生噪声。用 0.6B/1.7B 模型，甚至非 LLM 的小策略网络，扫一遍噪声/信号比，画出 GRPO、StepPO(M1)、M2-plain、M2 的样本效率曲线。审稿人最想看的就是"噪声越大，M2 优势越明显"这类图。真实数据上的 4B 实验做不出这么干净的图。

### 4. 把主实验改到算力能负担的规模
- **改用 LoRA，或者 1.7B 全参数**。分块 Adam、显存交接、磁盘 moments 这一套工程问题会直接消失，每轮更新快很多。这样才跑得起 ≥3 个 seed、每臂 ≥50 次更新。
- 现在每次更新只有 2 个窗口 × 4 条 sibling，太小，要加大每批窗口数。9-13 的 lessons 文档也提到，AlphaQuanter 的配置是每批 32 个 prompt、每个 16 条 rollout。

### 5. 重新设计评测，让统计站得住
- 一个 Final OOS episode 撑不起显著性检验。改用多个不重叠的样本外窗口（rolling-origin），或者扩展股票池和年份。
- 报告逐窗口配对差、block bootstrap 置信区间、胜率，再加 Sharpe 和 MDD。
- 外部基线：buy-and-hold、零样本前沿 API 模型、TradingAgents 类的纯提示方法。审稿人一定会问"RL 训练的 4B 是否比直接用 GPT 或 Claude 好"。

### 6. 设一个止损点，准备好退路
做完第 3 步和第 4 步后（大约 6–8 周），如果 M2−M1 仍不显著，可以转成以下两类论文之一：
- **分析型论文**："外生噪声主导时，LLM trading agent 的 credit assignment 为什么难"。合成环境加真实数据的负结果，也可以发。
- **Benchmark 论文**：仓库里防 look-ahead 泄漏的数据接口、point-in-time 的严格约束、冻结哈希的可复现评测协议，本身就适合投 NeurIPS Datasets & Benchmarks track。这部分已经做得比大多数金融 agent 工作扎实。

### 7. 精简流程
每个小试都写计划、修订、封存，严谨性值得肯定，但开销太大。建议：合成环境和规模调整这类探索性实验只做 append-only 的记录；正式预注册留到最终对比之前一次做完。
