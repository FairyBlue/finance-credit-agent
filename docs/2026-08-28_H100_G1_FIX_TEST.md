## 2. 为什么需要修复

`8a090b8` 的 H100 软件栈和旧 preflight 已通过，但真实 Qwen tokenizer 在第一次 generation 前就
测得 5,141 tokens，超过配置的 4,096；累积 tool history 后可增长到 40,285，已经超过模型
context 与 response 预算。因此当时主动停止，没有点火，也没有 optimizer 证据。

本分支没有合并旧脏工作树中的报告、W&B 方案、旧 lock、过期 draft 或 micromamba 补丁，只保留
并重新实现仍有价值的约束：

- `training.episodes=4` 同时约束 processed train 行数和上游 `data.train_max_samples=4`；
- 当前 session 的 20 个 ticker 行情始终各保留一条，signal 独立限制为最近 10 条；
- 每轮只暴露冻结任务、当前状态和最近工具结果，消息历史不再线性增长；
- retrieve 上限为 10，搜索范围与实际返回的紧凑证据一致；
- exact Qwen revision 固定为 `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`，actor/critic
  命令绑定 exact local snapshot，并强制 Hugging Face / Transformers offline；
- preflight 用真实 tokenizer 审计 train 和 valid，每个 session 同时覆盖 hold 路径、逐步建仓路径
  和最大 retrieve；
- source/reviewed/processed 的实际 SHA、行数、prompt 测量与 resolved model 都写入 summary；
- SETUP 的数据阶段保留 `--extra gpu`，后续实验命令统一使用 `uv run --no-sync`。

这些 observation/retrieve 变化属于协议级变化，已写入 `EVAL_PROTOCOL.md` v0.7 提案；必须由
合作者线下审核，旧 rollout 不得与新协议结果混用。
