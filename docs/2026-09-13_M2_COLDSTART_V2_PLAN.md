# 共同冷启动 v2：真实持仓与错误恢复

制定时间：2026-09-13 23:08 SGT（UTC+8）。状态：执行前方案。

本轮目标是让共同初始化候选根据当前仓位选择合法动作，并在拒绝后恢复。
用户已同意所有实验组共享先验；先稳定共同起点，再检验 M2 的 step reward
相对共同 SFT 和 M1 的增量。此次补充 SFT 本身不能证明 M2 有效。

## 1. 已知问题与共同接口

v1 的 SFT 使模型开始真实交易，但验收只有 99/100 条完整，207/846 次请求
非法。187 次是买入目标不高于当前仓位，16 次是卖出目标不低于当前仓位。
一次短回合在已有 MSFT 约 20% 仓位时反复请求买到 20%，耗尽请求预算。
这里没有 4096-token 截断，也没有丢失当前账户状态。

新增可选协议 `single_tool_portfolio_v1`，明确以下接口事实：

- `target_weight` 是交易后该股票的目标总仓位；不是增买、减卖的数量。
- 买入目标必须高于最新当前权重；卖出需有持仓且目标低于最新当前权重。
- 价格变化会改变权重；保持现有组合使用 `hold`，不需要重新提交持仓。
- 被拒绝的请求不会成交、不会推进日期；应读取错误和当前状态后重新决策。
- 股票与工具名称来自当前声明的接口。

这些说明统一提供给 v2 训练前后的模型，不添加选股、买卖信号、持仓比例规则、
动作屏蔽或非法动作自动修正。原协议保留原有行为与身份。仍使用 non-thinking、
当前历史特征观察、原交易环境和 vLLM；不扩展底层数值排查。

## 2. 训练数据：固定状态覆盖

从 v1 使用的前 20 个 Train windows 中选择能容纳前三步和后三个结果交易日
的决策日期，按日期排序每四个取一个。每个日期执行八种预先固定的三步前缀：

| 状态 | 三步前缀（目标总仓位） |
|---|---|
| cash | hold、hold、hold |
| single_low | GS 10%、hold、hold |
| single_high | MSFT 30%、hold、hold |
| pair_low | GS 10%、MSFT 10%、hold |
| pair_mixed | GS 25%、MSFT 15%、hold |
| triple_below | GS、MSFT、HD 各 19% |
| triple_above | GS、MSFT、HD 各 21% |
| triple_mixed | GS 10%、MSFT 20%、HD 30% |

前缀通过真实 ledger 执行，包含价格变化、佣金与滑点；观察显示实际当前权重。
这些前缀用于覆盖状态，不是推理时执行的投资规则。

每个干净状态产生一条自主决策示范和两条接口练习。自主示范沿用已披露教师：
在 GS/MSFT/HD 的合法买入 10%/20%、卖出 0%/10% 与 hold 中，比较后三个
交易日实际净终值后选标签。未来只进入离线教师标签，不进入模型观察。
该标签包含有限股票、仓位网格、短期事后择优的先验，不宣称中性或最优策略。
接口练习分别要求保持组合，以及执行明确给定的 10%/20%/30% 总仓位意图；
根据真实当前仓位选择 buy/sell/hold。自主验收不提供这些意图。

每个日期另增加四种真实拒绝后的自主示范：cash 中零持仓卖出；single_high
与 triple_above 中向更低目标买入；triple_mixed 中向更高目标卖出。
拒绝前后核对现金、持仓、日期及成交不变；保留错误反馈后再生成合法教师标签。
当前错误观察保留方向错误文字和完整当前仓位，未保留被拒请求的全部参数。
因此这里检验的是看到错误后重新选择合法动作，不宣称修复了原请求的投资意图。

从 v1 按类别内均匀位置回放 96 条（decision 76、api 20），重建原状态并使用
共同新协议重新渲染。总样本数不超过 1024；不依据收益做类别重采样。生成器
记录逐条来源、前缀、当前状态、标签候选结果及数据哈希，实际分布进入报告。

序列决策中模型所遇状态会受之前动作影响，这是补持仓及错误状态的依据。
相关方法讨论见 [Ross 等，AISTATS 2011](https://proceedings.mlr.press/v15/ross11a.html)。
本轮使用固定状态覆盖，不声称实施了完整 DAgger 或获得其理论保证。

## 3. 验收：旧回归与新增日期隔离状态

两个模型均为 4B：训练前使用 v1 merged SFT，训练后使用其补训后的 v2 merged
SFT。两者使用相同新协议、上下文、请求预算及 seed 身份。

旧回归原样保留 16 个短状态与四个完整 21-session 窗口，日期为 2023-06-14
至 2023-08-01。每个状态 1 greedy + 4 sampled，共 100 条。

screening Train 内没有被旧训练及验收使用的日期只剩 2023-05-23 至
2023-06-13，共 15 个 sessions。新增验收使用这一段，不借用 Dev/Test：

- 2023-05-23 至 06-01、06-02 至 06-12 两个七日片段，各覆盖八种上述状态。
  三步前缀后由模型自主运行剩余三步；其中四类状态再附一个不推进日期的真实
  非法前缀，检验错误恢复。共 16 个短状态。
- 2023-05-23 至 06-13 的 15-session 现金起始完整片段，一个状态。

每个状态仍 1 greedy + 4 sampled，共 85 条。15-session 片段单独标识，
不冒充原 21-session 窗口。历史特征可读取当时已知的更早日期；隔离的是
决策、教师未来标签和验收回放日期。原训练全部可见/标签日期截至 05-22。

旧、新两套分别调用评估，避免新增状态改变旧 grid 的 seed 索引。预置拒绝
只算状态构造，不计模型请求、非法率或成交；模型接管后的错误全部计入。
短请求上限 32、完整片段上限 128；prompt 8192、response 4096。
预算耗尽保留 INCOMPLETE，不以重跑清除失败。

主要读数：完整率、非法率与错误种类、真实成交股票及日期、已有持仓的增减与
保持、交易成本、现金比例、最大个股权重、四个 sampled siblings 的净收益差异。
收益只在完整轨迹上计算，前后差值仅对双方完整且身份相同的轨迹计算。
风险指标包含固定前缀时明确标注；模型成本与成交排除前缀。

## 4. 固定训练预算与推进条件

从 `runs/m2-coldstart-20260913/merged_model` 新建 LoRA，固定两轮、学习率
5e-5、rank 16、alpha 32、相同七类线性层、micro-batch 2、累积 8、seed 42。
BF16、SDPA、gradient checkpointing、completion-only + EOS loss；长度超限报错，
不截断训练示范。CPU merge 使用同一 v1 模型与新 adapter，不误合并到原始基座。
保留 adapter、optimizer/RNG、merged model 和完整训练记录。

在读取 v2 结果之前固定以下实用候选门槛，用来判断是否进入短 RL：

1. 两套验收均全部完整，各套模型非法请求率不超过 5%。
2. 新验收四类错误状态的 40 条轨迹全部完整，合计模型非法率不超过 5%。
3. 每套验收至少一半 sampled contexts 的四个完整 siblings 净收益差异大于
   1e-8，保证后续 RL 有不同真实结果可学习。
4. 两套合计至少一半完整 full sampled 轨迹，在至少两个不同日期有模型真实
   成交，避免退回全 hold；这不是多交易奖励，也不按买入次数选择 checkpoint。

成本、收益、集中度仍逐项报告，门槛通过不代表投资表现优秀。若出现明显的新
弱点，先解释具体轨迹再决定下一项有界修复。原候选及失败证据均保留。

共同起点通过后保留未 RL 的 v2 SFT 基线，再从完全相同的 actor checkpoint、
reference 与已修复共同 critic seed 进入 M1/M2 短 RL。比较的解释边界是
“在该共同 SFT 先验下 M2 的增量”，不把 SFT 收益归入 M2。RL 的具体运行
身份和资源检查在该门槛后记录；未通过则不启动。
